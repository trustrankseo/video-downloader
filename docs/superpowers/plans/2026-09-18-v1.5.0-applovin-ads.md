# Universal Downloader v1.5.0 AppLovin MAX Ads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.5.0 with AppLovin MAX banner + post-download interstitial monetization, while removing the current subscription UI and preserving all downloader behavior.

**Architecture:** Add a focused `AdsManager` and Compose banner bridge. The ViewModel exposes a one-shot completion event for whole download operations; the Activity/UI layer decides whether to show an interstitial. AppLovin initializes only after privacy consent.

**Tech Stack:** Kotlin, Jetpack Compose, AppLovin MAX Android SDK, Android SharedPreferences/BuildConfig, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-18-v1.5.0-applovin-ads-design.md`

## Global Constraints

- Package remains `com.faisal.freshdownloader`.
- App name remains `Universal Downloader`.
- Version becomes `1.5.0`; versionCode becomes `35`.
- Banner appears only on Downloader.
- Interstitial appears only after an operation with at least one successful download.
- Interstitial cooldown is 90 seconds.
- Ads never interrupt an active download.
- Subscription/Premium UI and Google Billing runtime dependency are removed.
- Existing production release signing stays unchanged.
- AppLovin initialization happens only after privacy consent.
- English + Simplified Chinese privacy disclosure must be updated.
