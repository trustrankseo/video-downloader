# Universal Downloader v1.5.0 AppLovin MAX Ads Design

**Date:** 2026-09-18

## Goal

Ship Universal Downloader v1.5.0 as an Uptodown-focused free build monetized with AppLovin MAX ads. Remove the current Google Play subscription/Premium purchase flow from this build. Keep Single, Bulk, and Channel/Profile download modes available without subscription gating.

## Approved ad model

- Banner ad on the main Downloader screen only.
- Interstitial ad only after a successful download flow completes.
- Minimum 90-second cooldown between interstitials.
- Ads must never block or interrupt an active download.
- If an ad is unavailable or fails to load, the app continues normally.
- No rewarded ads in v1.5.0.
- No subscription flow in v1.5.0.

## Architecture

Create a focused `AdsManager` responsible for AppLovin MAX SDK initialization, banner lifecycle, interstitial preloading, cooldown enforcement, and safe show/fallback behavior. Downloader logic reports successful completion through an event/state signal; UI decides when to request an interstitial so the ViewModel remains independent of Activity/SDK UI concerns.

The existing first-launch privacy gate remains the entry point. AppLovin SDK initialization must happen only after the user has accepted the privacy policy. Update English and Simplified Chinese privacy copy to disclose advertising SDK/device/advertising-identifier processing where applicable.

## Premium removal

Remove the visible Premium menu/page and Google Play Billing dependency for this Uptodown build. Remove subscription purchase/restore UI and any wording that tells users Bulk/Channel require trials or Premium. Bulk/Channel remain usable without subscription gating.

Do not delete historical billing code unless required for build cleanliness; prefer removing all runtime references and the Billing dependency so the v1.5.0 release does not initialize or depend on Google Play Billing.

## Ad placement

### Banner
Render a small AppLovin MAX banner anchored at the bottom of the Downloader screen, outside active controls and above navigation/system insets. It should not cover task rows, URL fields, buttons, or progress indicators.

### Interstitial
After a completed download operation:
- Single: eligible after the single task reaches COMPLETE.
- Bulk: eligible once after the whole bulk queue finishes and at least one task completed successfully.
- Channel/Profile: eligible once after the whole collection queue finishes and at least one task completed successfully.
- Never show once per item inside bulk/channel loops.
- Never show after failure-only runs, cancellation, discovery failure, or user stop.
- Enforce 90-second cooldown.
- Preload next interstitial after dismissal/failure.

## Privacy and consent

AppLovin initialization occurs only after `PrivacyConsentGate` has accepted the current privacy policy version. Update policy copy in both English and Simplified Chinese to disclose:
- advertising SDK use,
- device/app signals and advertising identifiers where available,
- use for ad delivery, measurement, fraud prevention, and frequency control,
- third-party processing by AppLovin and advertising partners,
- opt-out/controls available through device/app privacy settings where applicable.

Increment the privacy policy consent version so existing users see the updated policy once.

## Failure handling

- SDK init failure: app still works.
- Banner load failure: hide/leave empty ad space collapsed.
- Interstitial load failure: skip ad and continue.
- Interstitial show failure: skip ad, record cooldown only if an ad actually displayed.
- No ad code may throw into the download flow.

## Versioning

- versionCode: increment exactly once from current 34 to 35.

Build the normal production-signed release APK using the existing Huawei release signing configuration already used for trusted updates. Artifact name:

- banner appears only on Downloader,
